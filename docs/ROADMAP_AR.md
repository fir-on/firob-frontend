# منصة FirOb — خطة التنفيذ الجديدة (بناء من الصفر)
## البنية المعمارية: Laravel 12 + Livewire + Tailwind 4 + محرك ذكاء اصطناعي هجين

توضح هذه الوثيقة خطة التنفيذ الرئيسية لبناء منصة FirOb متعددة المستأجرين (SaaS) من الصفر بالكامل. تدمج الخطة جميع الأنماط المعمارية ووحدات الأمان التي صُمِّمت واعتُمدت سابقًا، إلى جانب ميزات الذكاء الاصطناعي المتقدمة، مثل مولّد الموارد الهجين بسبعة مشغّلات (7 Drivers)، ومسار عمل النشر، وانتحال هوية المستأجر (Tenant Impersonation).

---

## السبرنت 1: الأساس الجوهري وبنية تعدد المستأجرين بقاعدة بيانات واحدة
*الهدف: إرساء الطبقات الأساسية الثابتة (تعدد المستأجرين، قاعدة البيانات، المستودعات، الخدمات).*

1. **مخطط قاعدة البيانات وتعدد المستأجرين:**
   - إنشاء جداول `tenants` و`plans` و`subscriptions` و`tenant_settings` مع فهارس فريدة مركّبة صارمة `(tenant_id, key)`.
   - اعتماد مفاتيح أساسية من نوع ULID/BigInt، وأعمدة عدّادات التخزين (`cached_user_count` و`cached_storage_mb`).
2. **توحيد تحديد هوية المستأجر:**
   - بناء الوسيط `InitializeTenantContext` Middleware (يعالج انتحال الهوية عبر الجلسة، ومستأجر المستخدم المصادَق عليه، وترويسات `X-Tenant-ID` بعد التحقق منها).
   - ربط `currentTenantId` كنسخة وحيدة (Singleton) داخل حاوية الخدمات (Service Container).
3. **سمات Eloquent والنطاقات:**
   - بناء السمة `BelongsToTenant` والنطاق العام `TenantScope`، بحيث يقرآن حصريًا من `app('currentTenantId')`.
4. **البنية الأساسية:**
   - إنشاء `BaseRepository` و`BaseService` و`RepositoryServiceProvider`.
   - ضبط محددات المعدّل العامة (Rate Limiters) في `SecurityServiceProvider` (بما فيها `ai-generation` و`chatbot`).

---

## السبرنت 2: المصادقة، والتحقق الهجين بخطوتين، وهيكل لوحة التحكم
*الهدف: تأمين وصول المستخدمين، وإرساء تسلسل الأدوار الهرمي، وبناء هيكل التنقل.*

1. **Laravel Fortify والتحقق الهجين بخطوتين (2FA):**
   - ضبط مصادقة Fortify والتحقق بخطوتين عبر TOTP (`two_factor_confirmed_at`).
   - تنفيذ `TwoFactorRequirementService` و`EnforceSuperAdminTwoFactor` (إلزامي سيادي للمسؤول العام).
   - بناء واجهة الملف الشخصي لإدارة التحقق بخطوتين اختياريًا ورموز الاسترداد.
2. **إدارة المستخدمين وتسلسل الأدوار:**
   - تنفيذ `UserRoleEnum` مع مستوى رقمي `level()` وحارس `assignableBy()`.
   - بناء دعوات المستخدمين، وإسناد الأدوار، وحارس `LastAdminDeletionGuard` (منع حذف آخر مدير).
3. **هيكل لوحة التحكم وانتحال هوية المستأجر:**
   - بناء تخطيط تنقل متجاوب (شريط جانبي، مبدّل المستأجرين، الإشعارات، مبدّل اللغة).
   - تنفيذ **خدمة وسياسة انتحال هوية المستأجر** التي تتيح للمسؤول العام الدخول بأمان بصفة المؤسسات المستأجرة.

---

## السبرنت 3: طبقة التحكم والحوكمة (RBAC، الإعدادات، سجلات التدقيق)
*الهدف: حوكمة إدارية كاملة قبل إدخال المحتوى الأكاديمي.*

1. **محرر مصفوفة الأدوار:**
   - بناء مكوّن Livewire باسم `RoleMatrixEditor` (شبكة الصلاحيات × الأدوار مع تحديث فوري لصلاحيات Spatie ضمن نطاق الفريق).
   - تنفيذ إبطال ذاكرة التخزين المؤقت للصلاحيات عبر `forgetCachedPermissions()`.
2. **إعدادات المستأجر والنظام:**
   - بناء `TenantSettingsService` بنمط Cache-Aside عبر Redis مع إبطال فوري.
   - تنفيذ **سياسة التحقق بخطوتين على مستوى المستأجر** (`security.require_2fa`) مع حراس منع الإقفال الذاتي، والوسيط `EnsureTwoFactorEnforced`.
3. **مسار تدقيق النشاط:**
   - توسيع سجل نشاط Spatie بعمود `tenant_id` غير قابل للقيمة الفارغة، مع تطبيق `TenantScope`.
   - تنفيذ تسجيل تدقيق عبر الطوابير (Queued) مع التقاط السياق صراحةً لحظة الإرسال.
   - بناء عرض `ActivityTimeline` في لوحة التحكم بترقيم صفحات قائم على المؤشر (Cursor Pagination).

## السبرنت 4: الهيكل الأكاديمي والمحتوى الأكاديمي ومسار موارد الذكاء الاصطناعي الهجين
*الهدف: الهيكل الأكاديمي القابل للتهيئة لكل مؤسسة، والمواد الدراسية، والمفاهيم، والنظام الفرعي المتقدم لتوليد الموارد بالذكاء الاصطناعي متعدد المشغّلات.*

1. **الهيكل الأكاديمي للمؤسسة (قابل للتهيئة) — يُبنى أولًا داخل هذا السبرنت، وتفاصيله في `ACADEMIC_STRUCTURE_AR.md`:**
   - **القرارات:** المؤسسة تحدد هيكلها بحرية؛ المقرر (`Subject`) إلزامي دائمًا؛ الصف (`Grade`) والوحدة (`Unit`) والدرس (`Lesson`) اختيارية؛ المفهوم يُنسَّب للمقرر إلزاميًا وللصف/الوحدة/الدرس حسب إعدادات المؤسسة.
   - **طبقة البيانات:** جداول `grades` و`units` و`lessons`، وعمود `subjects.grade_id`، وعمودا `concepts.unit_id` و`concepts.lesson_id` (كلها اختيارية)، مع فهارس مركّبة تبدأ بـ `tenant_id` وقيود فريدة مركّبة؛ وترتيب الترحيل: `grades → subjects → units → lessons → concepts`.
   - **الإعدادات:** المفتاح `academic.structure` في `tenant_settings` (تفعيل/إلزام/تسمية AR-EN لكل مستوى) عبر `TenantSettingsService`، و`AcademicStructureService` مع كائن `AcademicStructureConfig`، وتبويب «الهيكل الأكاديمي» في `TenantSettingsForm` وخطوة في `TenantOnboardingWizard`.
   - **الخدمات والحراس:** `GradeService` و`UnitService` و`LessonService` و`StructureDeletionGuard` (حذف عنصر هيكلي لا يحذف المحتوى أبدًا) و`ConceptClassificationValidator` (تماسك الشجرة وعزل المستأجرين).
   - **الصلاحيات:** `configure-academic-structure` و`manage-academic-structure` و`view-academic-structure` ضمن `RoleMatrixEditor`.
   - **الواجهات:** شاشة الصفوف، وتبويبا الوحدات والدروس في تفاصيل المادة، وقوائم متسلسلة (مقرر ← وحدة ← درس) في محرر المفهوم، وفلاتر في قائمة المفاهيم، وتصفح هرمي للطالب.
2. **إدارة المواد الدراسية والمفاهيم (CRUD):**
   - بناء إدارة `Subject` قابلة للترجمة (مع `grade_id` حسب الإعدادات)، وإدارة `Concept` مع تعقيم HTML ضد هجمات XSS (`mews/purifier`)، وتطبيق قواعد التصنيف الإلزامي عبر `ConceptClassificationValidator` عند الإنشاء والتعديل وقبل الإرسال للمراجعة.
3. **نظام إدارة الموارد الهجين (الوحدة 3.2B):**
   - **طبقة البيانات:** جدول `ai_generation_jobs`، واتصال الطابور (`ai-generation`)، وجدول `concept_media` متعدد الأشكال (Polymorphic).
   - **تكامل 7 مشغّلات للذكاء الاصطناعي:** تنفيذ `AIProviderManager` بدعم `OpenAI` و`Ollama` و`FluxLocal` و`PiperLocal` و`ElevenLabs` و`Replicate` و`OpenRouter`.
   - **المولّدات:** هيكلة النصوص، والصوت (TTS)، والرسوم التوضيحية، والعروض التقديمية (PPTX)، وملفات PDF، و**مُصيِّر مستندات DOCX** (مع أصول القوالب).
   - **ميزات متقدمة:** إلغاء عمليات التوليد، ومساعد اقتراحات الذكاء الاصطناعي في نماذج المفاهيم، واختبار التحويل الاحتياطي بين المزوّدين.
   - **الحصص وتحديد المعدّل:** فرض حصص الرموز (Tokens) الشهرية عبر `PlanLimitEnforcementService` (باستخدام أقفال Redis مع معاملات قاعدة البيانات)، وتحديد المعدّل لكل مورد.
4. **مسار عمل نشر المحتوى:**
   - تنفيذ آلة الحالات `PublishingModeEnum` (`DRAFT` مسودة ← `PENDING` قيد المراجعة ← `PUBLISHED` منشور / `REJECTED` مرفوض) مع إجراءات الإرسال والاعتماد والرفض والإشعارات.

## السبرنت 7: البوابة العامة، وفوترة SaaS، والتكامل والنشر المستمر (CI/CD)
*الهدف: التوزيع العام، وتحقيق الإيرادات، والاختبار المؤتمت.*

1. **الكتالوج العام وبوابة العرض:**
   - بناء واجهات عامة معزولة (Sandboxed) لتقديم كائنات التعلّم.
2. **اشتراكات SaaS والفوترة:**

3. **أتمتة التكامل المستمر واختبارات الانحدار:**
   - ضبط GitHub Actions لتشغيل الاختبارات تلقائيًا.
   - بناء حِزم اختبارات موحّدة شاملة (End-to-End) لدورة حياة المستأجر، واختبارات انحدار أمنية.
